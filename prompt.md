# Build a Premium Student Software Engineer Portfolio

You are an expert frontend engineer, UI/UX designer, and product designer.

Build a **production-quality personal portfolio website for a student software engineer**.

The website must look like it was designed and built by a talented software engineer—not generated by AI.

The primary goals are:

1. Impress recruiters and engineering teams within the first 10 seconds.
2. Clearly communicate who I am, what I build, and what technologies I know.
3. Showcase projects as real engineering work rather than generic portfolio cards.
4. Make the website visually memorable without being flashy.
5. Maintain excellent readability, accessibility, responsiveness, and performance.
6. Make the codebase clean, reusable, and easy to maintain.

---

# 1. TECH STACK

Use:

* React
* Vite
* JavaScript or TypeScript
* Modern CSS
* CSS Modules where appropriate
* React Router if multiple pages/routes are genuinely useful
* Lucide React for icons
* Google Fonts

Do NOT introduce unnecessary frameworks or libraries.

Avoid adding dependencies simply to create visual effects.

The project should be easy to run with:

```bash
npm install
npm run dev
```

---

# 2. DESIGN DIRECTION

Create a **modern engineering portfolio**, somewhere between:

* premium developer portfolio
* startup engineer website
* technical résumé
* polished personal brand

The design should feel:

* professional
* mature
* minimal
* confident
* technical
* elegant
* slightly distinctive
* human-designed
* recruiter-friendly

It should NOT feel:

* like an AI-generated template
* like a SaaS landing page
* childish
* overly colorful
* excessively animated
* overly corporate
* like a generic Bootstrap portfolio
* like a Dribbble concept that sacrifices usability

### Important:

**Professionalism is more important than visual effects.**

Use whitespace, typography, spacing, hierarchy, alignment, and subtle details to create quality.

---

# 3. VISUAL STYLE

Use a refined neutral palette.

Suggested direction:

Background:

* warm/off-white or very dark charcoal depending on the chosen theme

Primary text:

* near-black / near-white

Secondary text:

* muted gray

Accent:

* ONE sophisticated accent color

Do not use rainbow gradients.

Do not use excessive purple/blue AI-style gradients.

Do not cover the page with glowing blobs.

Do not use glassmorphism everywhere.

Do not use excessive rounded cards.

Use borders and subtle elevation sparingly.

---

# 4. TYPOGRAPHY

Use Google Fonts.

Choose a professional combination such as:

Primary:

* Inter
* Geist
* Manrope
* Plus Jakarta Sans

Technical/monospace:

* JetBrains Mono

Use typography intentionally.

For example:

large, bold, tight line-height

JetBrains Mono

Navigation:

# 7. HERO SECTION

The hero is extremely important.

It should immediately communicate:

Who I am
What I do
What technologies I work with

Example structure:

Small eyebrow:

```text
SOFTWARE ENGINEER · STUDENT
```

Large headline:

```text
Building reliable software
with a focus on backend systems
and modern web applications.
```

Then a short, natural description.

Example:

```text
I'm a student software engineer focused on Java, Spring Boot,
React, distributed systems, and building practical products
that solve real problems.
```

Do NOT use generic AI-generated phrases such as:

"I am a passionate developer who loves turning ideas into reality."

Make the copy concise and technically credible.

Hero CTA:

* View Projects
* GitHub
* Download Resume

Optional secondary status indicator:

```text
● Currently building & learning
```

Keep it subtle.

# 20. ANIMATIONS

* smooth scrolling

* button micro-interactions

* project image movement

* cursor-following effects

Respect:

Keep content separate from components wherever practical.

For example:

```js

  {
    title: "Credencify",

    demo: "..."
  }

```

Do not hard-code every project directly into JSX.

# 31. FINAL QUALITY CHECK

Before considering the task complete, inspect the entire site as if you were a senior frontend engineer reviewing a candidate's portfolio.

Check:

### Visual

* Does it look professionally designed?
* Does it look human-made?
* Is spacing consistent?
* Is typography excellent?
* Are there too many cards?
* Are there too many effects?
* Is anything visually unnecessary?

### Technical

* Does the project build successfully?
* Are components reusable?
* Are there console errors?
* Are links valid/placeholders obvious?
* Is responsive behavior correct?

### UX

* Can a recruiter understand who I am in 5–10 seconds?
* Can they find my projects immediately?
* Can they access GitHub and LinkedIn easily?
* Is the resume easy to find?
* Does mobile feel intentionally designed?

### Content

Remove generic filler.

Every sentence should communicate something useful.
